# E6 — Read-only diagnostics and operational automation

**Completed:** 2026-11-27. **Scope:** local implementation, source review, and synthetic/loopback tests only. No Azure, Azure DevOps, Kubernetes, external-host, Log Analytics, or billing query was run.

## Delivered

- `tools/azure_inventory.py` performs explicitly scoped, read-only Azure Resource Graph inventory. It requires a subscription UUID, optionally filters one strictly validated resource-group name, projects only `id`, `name`, `type`, `resourceGroup`, `subscriptionId`, and `location`, and orders by resource ID. By default, each resource ID/name is represented by a stable SHA-256 reference; tags and dynamic properties are neither queried nor returned.
- The inventory uses `az graph` when its extension is installed and falls back to the built-in `az rest` Resource Graph query endpoint otherwise. REST request bodies put the same explicit subscription and query in a short-lived JSON file passed with Azure CLI's documented `@file` syntax; the file is removed after the request. The tool will not install extensions, log in, enumerate accounts, select a default subscription, or change CLI configuration. Each page supplies the same explicit subscription. Page size is 1–1000, page count is capped at 100, each CLI process has a 1–300 second timeout, retries are capped at five with bounded exponential delay, and repeated continuation tokens, duplicate IDs, count mismatches, changing totals, truncated responses and incomplete pagination fail closed. Resource Graph is not a point-in-time snapshot, so concurrent inventory changes remain a documented limitation.
- Structured outcomes distinguish complete, empty, usage, authentication, permission, timeout, incomplete, query and local dependency states. Exit codes are `0` complete, `2` empty, `3` usage, `4` authentication, `5` permission, `6` timeout, `7` incomplete, `8` query failure, and `9` local dependency failure. Raw Azure CLI error text is suppressed.
- `tools/diagnostic_catalog.json` defines all thirteen requested diagnosis areas: DNS, routes, TCP/TLS, effective NSG, Private Endpoint/DNS, identity, token audience, RBAC, Key Vault, Azure Policy, Kubernetes image pull, application health, and monitoring. The catalog and every cloud example remain `DOCUMENTED_NOT_RUN`; Key Vault secret-list metadata requires explicit owner approval because names can be sensitive.
- `tools/network_probe.py` performs direct DNS/TCP/TLS and unauthenticated HTTP HEAD probes. It races resolved addresses within the connection deadline, verifies HTTPS with the system trust store, does not inherit proxies, follow redirects, send credentials, or read a body, and redacts resolved IPs by default. The configured DNS wait is bounded, but Python cannot cancel an OS `getaddrinfo`; such lookup runs in a daemon thread until the resolver returns.
- `tools/token_audience.py` accepts an existing JWT through hidden terminal input or standard input and reports an allowlist of claims without echoing the token. It does not obtain a token or validate the signature, issuer, tenant, token type, or authorization; claim values remain untrusted.
- Five supplemental KQL templates were added to the AZ05-02 telemetry lab. They cover failed Azure Activity operations, Heartbeat freshness, sampled request failures, dependency failures, and exception groups. Each query states its schema assumptions, bounded lookback, purpose, and `NOT_RUN` status. Their schema was checked against Microsoft Learn table references, but syntax was not compiled and no workspace was queried.

## Resource Graph REST fallback follow-up — 2026-11-28

- When the local Resource Graph extension was absent, a read-only explicit-subscription query through `az rest` returned three `microsoft.network/networkwatchers` records in one page without truncation. Resource names and IDs were not retained; no Azure resource or provider changed.
- `azure_inventory.py` now selects `az graph` when available and falls back to the documented REST endpoint otherwise. The fallback preserves the explicit subscription scope, bounded page size, `$skipToken` pagination, retry policy, redaction and completeness checks. The Windows runner invokes the Azure CLI package's bundled Python directly when `az` resolves to a `.cmd` shim, avoiding shell argument parsing; temporary request JSON is removed after each call.
- The focused inventory suite passed 19 tests, including REST body scope, pagination, missing-extension fallback, temporary-file cleanup and string-encoded `resultTruncated`. The complete Windows Python suite passed 530 tests across 24 directories. The same inventory tool then completed a live read-only query through `az rest`: one page, three Network Watchers, complete result. This is current inventory evidence only and not a point-in-time snapshot.
